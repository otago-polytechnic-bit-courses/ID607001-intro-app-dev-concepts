# Marking Rubric

## System Design - Learning Outcome 1 (10%)

| Grade | A (10-8) | B (7.5-6.5) | C (6-5) | D/E (4.5-0) |
|-------|----------|-------------|---------|-------------|
| **Report** | **Comprehensive report with:** <br/>• Sophisticated application architecture explained <br/>• ERD shows complex relationships with correct normalisation <br/>• Data management approaches are well explained <br/>• All API endpoints documented with complete HTTP methods, routes and parameters <br/>• Design choices demonstrate deep understanding of scalability, maintainability, and performance with specific examples and justifications | **Well-structured report with:** <br/>• Clear application architecture explained <br/>• ERD shows appropriate relationships with good normalisation <br/>• Data management approaches are sound and justified <br/>• Most API endpoints documented with HTTP methods, routes and parameters <br/>• Design choices demonstrate good understanding of scalability, maintainability and performance with some justification | **Adequate report with:** <br/>• Basic application architecture explained <br/>• ERD shows fundamental relationships but may have normalisation issues <br/>• Data management approaches are basic but functional <br/>• API endpoints documented with HTTP methods and routes <br/>• Design choices demonstrate fundamental understanding of scalability, maintainability and performance with limited justification | **Insufficient report with:** <br/>• Unclear or missing application architecture <br/>• ERD is poorly designed or contains major errors <br/>• Data management approaches are unclear or inappropriate <br/>• API endpoints missing or incorrectly specified <br/>• Design choices demonstrate poor understanding of scalability, maintainability and performance |

## UI Design - Learning Outcome 1 (10%)

| Grade | A (10-8) | B (7.5-6.5) | C (6-5) | D/E (4.5-0) |
|-------|----------|-------------|---------|-------------|
| **Report** | **Comprehensive report with:** <br/>• Sophisticated responsive design strategies for multiple screen sizes <br/>• UI/UX decisions are well-justified with user-centered design principles <br/>• Navigation and interactions are intuitive, and accessibility focused <br/>• Professional wireframes/mockups for all key screens with detailed annotations showing layout rationale and user flow | **Well-structured report with:** <br/>• Good responsive design considerations <br/>• UI/UX decisions are justified with some user-centered principles <br/>• Navigation and interactions are generally intuitive <br/>• Wireframes/mockups for main screens with basic annotations | **Adequate report with:** <br/>• Basic responsive design considerations <br/>• UI/UX decisions have limited justification <br/>• Navigation and interactions are functional but basic <br/>• Basic wireframes/mockups with minimal annotations | **Insufficient report with:** <br/>• Little to no responsive design considerations <br/>• UI/UX decisions are poorly justified or missing <br/>• Navigation and interactions are confusing or non-functional <br/>• Missing or very poor wireframes/mockups |
