\section*{Assessment Overview}
In this \textbf{individual} assessment, you will develop a \textbf{REST API} using \textbf{Express} and \textbf{Node.js}, and deploy it as a \textbf{web service} on \textbf{Render}. You will choose the idea for the \textbf{REST API}. It could be related to sport, culture, food or something else you are interested in. \\


In \textbf{development} and \textbf{testing}, your data will be stored in a \textbf{PostgreSQL} database on \textbf{Docker} and in \textbf{production}, your data will be stored in a \textbf{PostgreSQL} database on \textbf{Render}. As you develop your \textbf{REST API}, you will need to write \textbf{API tests} to verify the functionality of your \textbf{REST API} using \textbf{Chai} and \textbf{Mocha}. \\

For marking purposes, provide a video demonstrating the functionality of your \textbf{REST API} and the \textbf{API tests}. Marks will also be given for code quality and best practices, documentation and \textbf{Git} usage.

\section*{Instructions}

\subsection*{Functionality - Learning Outcome 1 (50\%)}
\begin{itemize}
	 
	\item Models (5\%)
	\begin{itemize}
		\item Ten models. Each model must have at least five fields. One model must be the \textbf{User} model.
		\item A range of data types, i.e., \textbf{Int}, \textbf{String}, \textbf{Boolean}, etc.
		\item Five relationships between models, i.e., one-to-one, one-to-many, many-to-many, etc.
		\item Three enums. Each enum must have at least three values.
	\end{itemize}

	\item Authentication and Role-Based Access Control (10\%)
	\begin{itemize}
		\item Three roles, i.e., \textbf{SUPER\_ADMIN}, \textbf{ADMIN} and \textbf{NORMAL}.
		\item Register a \textbf{NORMAL} user, but not a \textbf{SUPER\_ADMIN} or \textbf{ADMIN} user. 
		\item All users can login.
		\item Lock a user for ten minutes after five failed login attempts.
		\item All users can logout. When a user logs out, the user's token is blacklisted. 
	\end{itemize}

	\item CRUD Operations (15\%)
	\begin{itemize}
		\item A \textbf{repository}, \textbf{controller} and \textbf{route} file for each \textbf{model}. Each \textbf{controller} file needs to contain the following CRUD operations: \textbf{getAll}, \textbf{getById}, \textbf{create}, \textbf{update} and \textbf{delete}.
		
		\item When performing \textbf{create} and \textbf{update} operations, validate the request body. Each field must have four validation rules.
		
		\item \textbf{Filter} and \textbf{sort} data using \textbf{query parameters}. All \textbf{fields} must be filterable and sortable (in ascending and descending order).
		
		\item \textbf{Paginate} data using \textbf{query parameters}. The default number of data per page is 25.

		\item \textbf{SUPER\_ADMIN} Permissions
		\begin{itemize}
			\item Can perform the following operations on the \textbf{User} model:
			\begin{itemize}
				\item \textbf{getAll} and \textbf{getById} operations on all users.
				\item Create, update and delete \textbf{ADMIN} and \textbf{NORMAL} users, but cannot update their \textbf{password}.
				\item Create a \textbf{SUPER\_ADMIN} user.
				\item Update their data except \textbf{role}, but not other \textbf{SUPER\_ADMIN} users.
				\item Cannot delete other \textbf{SUPER\_ADMIN} users, including themselves.
				\item Disable and enable users. When a user is disabled, the user cannot login.
			\end{itemize}
			\item Perform CRUD operations on the other models.
		\end{itemize}
		
		\item \textbf{ADMIN} Permissions
		\begin{itemize}
			\item Can perform the following actions on the \textbf{User} model:
			\begin{itemize}
				\item \textbf{getAll} and \textbf{getById} operations on \textbf{ADMIN} and \textbf{NORMAL} users, but not \textbf{SUPER\_ADMIN} users.
				\item Create, update and delete \textbf{NORMAL} users, but cannot update their \textbf{password}.
				\item Cannot create, update and delete \textbf{SUPER\_ADMIN} and \textbf{ADMIN} users.
				\item Update their data except \textbf{role}, but not other \textbf{ADMIN} users.
				\item Cannot delete other \textbf{ADMIN} users, including themselves.
			\end{itemize}
			\item Perform CRUD operations on the other models.
		\end{itemize}
		
		\item \textbf{NORMAL} Permissions
		\begin{itemize}
			\item Can perform the following actions on the \textbf{User} model:
			\begin{itemize}
				\item \textbf{getAll} and \textbf{getById} operations on themselves, but not other users.
				\item Update their data except \textbf{role}, but not other users.
				\item Cannot delete other users, including themselves.
			\end{itemize}
			\item Perform \textbf{getAll} and \textbf{getById} operations on the other models.
		\end{itemize}
	\end{itemize}

	\item Seeding and API Tests (10\%)
	\begin{itemize}
		\item Seed five \textbf{NORMAL} users via a \textbf{CSV} file.
		\item Seed five \textbf{ADMIN} users via a \textbf{JSON} file.
		\item Seed five \textbf{SUPER\_ADMIN} users via \textbf{GitHub Gist}.
		\item Provide the following \textbf{API tests}:
		\begin{itemize}
			\item CRUD operations for each model.
			\item Filter and sort data for each model.
			\item Pagination for each model.
			\item Authentication and role-based access control.
			\item Limit the number of requests for CRUD operations.
		\end{itemize}
	\end{itemize}

	\item Logging and Security (5\%)
	\begin{itemize}
		\item Log all requests and responses in development to a file called \textbf{combined.log}.
		\item Secure the \textbf{X-Powered-By} header.
		\item Limit the number of requests for \textbf{getAll} and \textbf{getById} operations to 20 requests within a 2 minute window. Set the message to \textbf{You have exceeded the number of requests: 20. Please try again in 2 minutes.} when the limit is reached.
		\item Limit the number of \textbf{create}, \textbf{update} and \textbf{delete} operations to 10 requests within a minute window. Set the message to \textbf{You have exceeded the number of requests: 10. Please try again in 1 minute.} when the limit is reached.
	\end{itemize}

	\item Development, Testing and Production (5\%)
	\begin{itemize}
		\item Environment variable key's are stored in a \textbf{.env} file.
		\item Use \textbf{/api/v1} as the base URL for the \textbf{REST API}.
		\item Use \textbf{Docker} to run the \textbf{PostgreSQL} database in development and testing.
		\item Use \textbf{Render} to run the \textbf{PostgreSQL} database in production.
		\item Deploy the \textbf{REST API} as a \textbf{web service} on \textbf{Render}.
	\end{itemize}
\end{itemize}

\subsection*{Code Quality and Best Practices - Learning Outcome 1 (40\%)}
\begin{itemize}
    \item Project Structure (10\%) - The codebase should be well-organised with a clear and logical structure that separates concerns and promotes reusability and maintainability.
	\item Naming Conventions (5\%) - File, class, function, variable and resource group names should be clear, descriptive and consistent across the codebase. 
    \item Documentation and Comments (5\%) - The codebase should be well-documented using the \textbf{JSDoc} format with comments that explain complex logic and clarify the purpose of classes, functions or complex sections. 
    \item Code Formatting (5\%) - Consistent indentation and spacing should be used across the codebase. It includes ensuring proper indentation for code blocks, following a standard format for braces and adding blank lines between sections. It should be automated using a tool like \textbf{Prettier}.
    \item Dead Code (5\%) - The codebase should not contain unused or redundant files, classes, functions, variables or resource groups. Keeping unnecessary codebase around can lead to confusion, clutter and potential bugs down the line.
    \item Performance and Scalability (10\%) - The codebase should be optimised for performance, using efficient algorithms and data structures to minimise bottlenecks. 
\end{itemize}
